# AI 기억장 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude/ChatGPT 대화에서 나온 업무 개념을 MCP로 받아 개념 노트로 합치고, 아이폰 홈 화면 웹앱에서 간격 반복 복습(빠른/깊은 모드)을 시키는 1인용 앱.

**Architecture:** Vite+TypeScript PWA(프론트, Vercel 정적 배포) ↔ Supabase Edge Function `api` 하나(앱 REST + `/mcp/<secret>` MCP 엔드포인트 + `/cron/remind`) ↔ Supabase Postgres. 서버 AI(개념 매칭·노트 합치기·채점·비교 질문)는 Anthropic SDK 구조화 출력. DB는 함수만 접근(service role), 바깥 직접 접근 차단 — '말해영어'와 같은 방식.

**Tech Stack:** Vite 8, TypeScript, Vitest(프론트), Deno test(서버), Supabase(Postgres, Edge Functions, pg_cron), `npm:@anthropic-ai/sdk`, `npm:web-push@3.6.7`, Vercel.

**Spec:** `ai-memory/docs/superpowers/specs/2026-11-21-ai-memory-design.md`

## Global Constraints

- 모든 코드는 `ai-memory/` 안에. 저장소 루트의 '말해영어' 파일·빌드·`.github/workflows/deploy.yml`은 건드리지 않는다.
- Supabase는 **새 프로젝트**(말해영어와 분리).
- 시간대는 `Asia/Seoul` 고정. "오늘" = 서울 기준 00:00~24:00.
- 대화당 후보 최대 **3개**. 받은함에서 확정 전에는 복습에 들어가지 않는다.
- 간격(단계별): 새(0) → 1일 → 3일 → 1주 → 2주 → 1달(30일) → 2달(60일) → 4달(120일, 마스터=7).
- 알았음: 다음 단계. 애매: 단계 유지, 간격 절반. 몰랐음: **두 단계 뒤로**(최소 0).
- 하루 목표 기본 **5**(설정 가능), 밀려도 상한 초과 출제 금지.
- 해설은 답을 시도한 뒤에만 노출.
- 노트 내용은 무료 등급 AI/임베딩 서비스로 보내지 않는다. 서버 AI는 Anthropic API만.
- 서버 AI 모델은 `app_config.ai_model`로 바꿀 수 있게. 기본 **`claude-haiku-5-5`**(사용자 결정), `output_config.effort: "low"`, `client.messages.create`(Haiku 5.5는 서버 측 fallbacks 미지원이라 넣지 않음). `stop_reason === "refusal"`이면 AI 결과 없음으로 처리.
- UI 문구는 한국어, 한 손 조작(버튼 최소 높이 56px), 다크 모드 지원.
- 1차 범위 밖: ZIP 가져오기, 음성 녹음(키보드 받아쓰기로 대체), 정식 앱.

### Task 2: 간격 반복 계산 (`srs.ts`)

**Files:**
- Create: `ai-memory/supabase/functions/api/srs.ts`, `ai-memory/supabase/functions/api/srs.test.ts`

**Interfaces:**
- Produces:
  - `type Grade = 'good' | 'hard' | 'again'`
  - `INTERVALS_DAYS = [0, 1, 3, 7, 14, 30, 60, 120]`, `MASTERED = 7`
  - `interface SrsState { stage: number; reviews: number; lapses: number }`
  - `schedule(s: SrsState, g: Grade, now: Date): SrsState & { due: Date }`
  - `firstDue(now: Date, slots: Slots): Date` — `Slots = { morning: string; evening: string; bedtime: string }`(서울 HH:MM)
  - `onMerge(due: Date, now: Date): Date` — `min(due, now+1일)`
  - `seoulDayEnd(now: Date): Date` — 서울 기준 오늘 23:59:59.999

규칙(스펙 고정값): good → stage+1(최대 7), due = now + INTERVALS_DAYS[new stage]일. hard → stage 유지, due = now + max(12시간, INTERVALS_DAYS[stage]/2일). again → stage = max(0, stage-2), lapses+1, due = now + 12시간. firstDue = now+1시간 이후 가장 이른 `bedtime` 또는 `morning` 슬롯.

- [ ] **Step 1: 실패하는 테스트**
```ts

Deno.test('hard: 단계 유지, 간격 절반(최소 12시간)', () => { assertEquals(hours(schedule({stage:4,...},'hard',T).due,T), 7*24); assertEquals(hours(schedule({stage:0,...},'hard',T).due,T), 12); });
Deno.test('again: 두 단계 뒤로, 최소 0, lapses+1', () => { assertEquals(schedule({stage:5,...},'again',T).stage,3); assertEquals(schedule({stage:1,...},'again',T).stage,0); });
Deno.test('마스터 초과 금지', () => assertEquals(schedule({stage:7,...},'good',T).stage,7));
Deno.test('firstDue: 서울 22:30 저장 → 다음 날 07:30', ...);   // 23:00은 1시간 이내라 건너뜀
Deno.test('firstDue: 서울 14:00 저장 → 같은 날 23:00', ...);
Deno.test('seoulDayEnd: UTC 15:10(서울 00:10)은 서울 그날 끝', ...);
Deno.test('onMerge: 10일 뒤 due → 1일 뒤로 당김, 3시간 뒤 due는 그대로', ...);
```
